# ADR-001: Android nativo (Kotlin + Jetpack Compose) em vez de Flutter, React Native ou apps nativos separados

| Item | Registro |
|---|---|
| Status / Data | ☑ Aceita · 11/11/2026 |
| Contexto | Global Solution com prazo de um semestre, equipe de 1 a 3 pessoas, stack trabalhada na disciplina (Android, Kotlin, Compose), público-alvo com aparelhos simples e uso frequente offline. O app precisa de recurso nativo com permissão (notificação) e de testes de domínio rápidos. |
| Decisão | Decidimos usar **Android nativo com Kotlin e Compose**, com domínio em Kotlin puro e contratos entre camadas. |
| Alternativas consideradas | **Flutter**: bom para 2 plataformas, mas exigiria aprender outra linguagem e outro ecossistema no mesmo prazo; o requisito não pede iOS. **React Native**: mesma lógica, mais a ponte para recursos nativos (notificação/permissão). **Dois apps nativos**: duplicaria interface e testes sem ganho para o escopo. |
| Consequências positivas | Menor risco de prazo (stack conhecida); acesso direto a permissões e notificações; desempenho previsível em aparelho fraco; domínio e contratos sobrevivem a uma troca futura de framework. |
| Consequências negativas | Sem versão iOS nesta entrega; uma só base de interface (Compose/Android). Custo aceito: o público-alvo do recorte é Android. |

**O que descartei, por qual critério e o que isso custa:** descartei Flutter/React Native por *prazo, equipe e experiência no Android*; o custo é não haver versão iOS nesta entrega.
